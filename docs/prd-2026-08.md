## 3. 需求明细

### 批次 1 —— 修错止血（agent 可独立完成，半天）

**R1 · auto-sync 与 sync-skills 修复**（源自审计仅有的两个 high 问题）

- 问题：① `auto-sync-skills.sh:99` 只 `git add src/content/skills`，`sync-skills.mjs` 的 `rmBoth`（:240-249）在 skillsEn 侧做的删除（EXCLUDE 撤下项、prune 孤儿）留在工作区不进 commit；② `:62` 的 `git diff --quiet` 不识别 untracked 新文件，纯新增同步会被判「无变化」退出；③ `:74-76` 中英对齐只比 `wc -l` 文件数，zh 缺 A / en 多 B 数量相等照样放行。
- 做法：
  1. `:62` 改为 `[ -z "$(git status --porcelain -- src/content/skills src/content/skillsEn)" ]` 判空退出；`:67` 的 CHANGED 统计改用同一 porcelain 输出；`:99` 改为 `git add src/content/skills src/content/skillsEn`。
  2. `sync-skills.mjs` 写模式下 enMissing / enExtra 非空也 exit 1（目前仅 `--check` 分支 exit 1，见 :316-320；auto-sync 走写模式，slug 级信息被丢弃）——落地后 shell 里的 `wc -l` 对比可删。
  3. `--check` 真只读：`:99` mkdir 与 `:265-270` .gitkeep unlink 包进 `if (!CHECK)`。
  4. 「无实质变化不改写」逻辑已存在（:200-211）但失效——根因是 gray-matter 对 `description: |` 块标量解析出尾随 `\n` 导致比较恒不等，修比较前先归一尾部空白（校验员实测定位，不要重写整段逻辑）。
- 验收：造夹具验证「纯新增」「en 侧删除」「en 多余」三个场景（注意 §9.12：容器内用 `zz-*` 临时夹具、验完即删）；`pnpm build` 过。
- 注意：§5.4.2 第 5 坑——改 auto-sync 脚本后**第一次自动跑行为以旧版本为准**。

**R2 · OG 分享兜底**

- 问题：`Base.astro:24` 无 image 时不输出 og:image，但 `:49` 无条件声明 `twitter:card=summary_large_image`，全站 150+ 页声明与实际不符；`weekly/[slug].astro:15`（zh/en）硬编码借用 `/og/c-suite.png`，图不对题。

**R3 · about 名片止血**

## 4. 开发计划（建议排期）

```
批次 1  修错止血       R1 R2 R3 R4 R14      ~半天   agent 独立，一个 PR
批次 2  工程护栏       R5 R6 R10 R15        ~1-2 天 agent 独立，CI 单独 PR 便于验证红绿
批次 3  发版与文档     R7 R8                ~1 天   在批次 1-2 合入后做（CHANGELOG 才完整）
批次 4  能力与内容     R9 R11 R12 R13       ~2-3 天 可拆散，R9 优先（agent 价值最高）
                      R16 R17 R18                  R16 部分等人喂 cloc 数据
批次 5  演进项         R19 R20 R21          按需    每项独立立项，R19 依赖 R9
用户线  R22 R23 + publish/Release/W32       随时    与批次并行，互不阻塞
```

原则：

1. **每批次都走 §15 回路**（计划 → 改 → `pnpm build` 验证 → dev-log），批次 1 的 R1 必须带夹具场景测试。
2. **批次 3 排在 1-2 之后**：让 0.4.0 的 CHANGELOG 把止血与护栏一并收进去，一次发版讲完整故事。
3. **R9 是批次 4 的头**：它是「不抓 HTML 走 JSON」承诺的补全，且解锁 R19（MCP 工具集）与 CLI 0.3.0。
4. **用户线不阻塞任何批次**：avatar / bio / W32 / publish / Release / Mac 同步都可穿插。
5. 优先级冲突时按「先堵泄漏（R1）→ 再上护栏（R5/R10）→ 再补能力」的顺序裁决。

## 5. 明确不做的事（本轮再次确认，沿用 AGENTS §14.5）

- 不做 CF Worker / 任何服务端运行时——MCP 走 CLI 子命令（R19），站点保持纯静态。
- 不做服务端搜索——语料 76 条，距 MiniSearch 阈值（200+）尚远；R9 落地后 search.json 语料变大，届时复核这个阈值即可。

- 不顺手升 Astro 大版本（R21 只评估）。
- 不做评论 / 写入类功能——演进路径里的「GitHub Issues API」方案维持挂起，等有真实需求。
